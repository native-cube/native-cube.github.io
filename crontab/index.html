    05 / Know the syntax

    Crontab syntax: the five cron fields

    A standard cron expression has minute, hour, day-of-month, month, and day-of-week fields. It describes wall-clock matches, not a fixed elapsed interval. AWS Scheduler adds a sixth field for the year.

    Read from left to right

    ┌────── minute       0–59
│ ┌──── hour         0–23
│ │ ┌── day of month 1–31
│ │ │ ┌ month        1–12
│ │ │ │ ┌ day of week
* * * * *

    Sunday is 0 in standard cron (Linux also accepts 7). AWS uses 1 for Sunday through 7 for Saturday. Names such as MON and JAN reduce ambiguity.

    Use the building blocks

    *
    Every value in a field
    ,
    A list: 0,15,30,45
    -
    An inclusive range: MON-FRI
    /
    A step: */15 or 9-17/2
    ?
    AWS: leave one day field unspecified. Kubernetes: wildcard.

    */35 in minutes means minute 0 and 35 of each hour. The gaps alternate between 35 and 25 minutes.

    Handle calendar boundaries

    With standard cron, restricting both day fields matches either one. 0 9 1 * MON runs on the first of the month and every Monday.

    AWS requires exactly one day field to be ?. It also supports L (last), W (nearest weekday), and # (nth weekday), for example MON#2.

    A day that does not exist never matches. Use L in AWS mode for the last day of every month.

    07 / Scheduler differences

    Linux, Kubernetes, GitHub Actions, and AWS cron syntax

    Choose the platform before validating an expression. These notes explain what the preview models and what to verify before deployment.

    Linux cron

    Five fields; Sunday 0 or 7; common @hourly through @yearly macros. This preview models Cronie-style wall-clock matching: missing times are skipped and repeated times appear twice.

    CRON_TZ is implementation-specific. Other cron daemons may compensate for clock changes differently.

    Read the crontab manual ↗

    Kubernetes CronJob

    Five fields; Sunday 0–6; macros and ? wildcards. Exports include spec.timeZone, stable since Kubernetes 1.27, and concurrencyPolicy: Forbid.

    The preview skips missing local times and lists repeated ones. Job creation is approximate; deadlines and concurrency can change actual runs.

    Read the CronJob documentation ↗

    GitHub Actions

    Five fields; Sunday 0–6; no macros. UTC is the default; the generated workflow sets timezone explicitly. The minimum supported interval is five minutes.

    Missing local times advance to the first valid time. For repeated times this preview uses the first occurrence; GitHub does not document that edge case. Workflows can be delayed or dropped under load.

    Read the schedule event documentation ↗

    AWS EventBridge Scheduler

    Six fields with year 1970–2199. Exactly one day field must be ?. Supports last-day L, nearest-weekday nW, last-weekday nL, and nth-weekday n#1 through n#5.

    Missing times are skipped; repeated times run once. Exports are schedule properties; add your name, target, and execution role separately. EventBridge rules are a different service.

    Read the Scheduler documentation ↗
    08 / Frequently asked questions

    Crontab and cron expression FAQ

    What is the difference between cron and crontab?

    Cron is a scheduler that runs tasks at matching times. A crontab is a table of those schedules and their commands. In a standard user crontab, each job line starts with five schedule fields followed by the command. Paste only the schedule fields into this tester.

    How do I schedule a cron job every five minutes?

    Use */5 * * * * in a five-field crontab. It matches minutes 0, 5, 10, and so on through 55 of every hour. In AWS Scheduler mode, use cron(*/5 * * * ? *). Choose the scheduler first because the field counts and day rules differ.

    How do I run a cron job every day at midnight?

    Use 0 0 * * * for Linux, Kubernetes, or GitHub Actions. Midnight is evaluated in the scheduler's configured time zone. In AWS Scheduler mode, use cron(0 0 * * ? *). Preview the next runs to check the UTC equivalents.

    How do I test a cron expression?

    Choose a scheduler, paste the expression, and select the time zone used by the actual scheduler. Review upcoming local and UTC times, then move the preview start to a month boundary or clock change. This builder calculates matches locally and does not run your task.

    Does a cron expression include a time zone?

    The expression describes calendar fields; the scheduler supplies the time zone. This tool exports a separate time-zone setting for each platform. A fixed UTC offset such as UTC+1 is not equivalent to Europe/London, whose offset changes during the year.

    Why does an expression with six fields fail?

    Six-field formats are not interchangeable. AWS Scheduler uses a final year field, while Quartz commonly adds seconds at the beginning and has different rules. Select AWS mode for AWS schedules. Quartz, seconds-based expressions, rate expressions, and @reboot are not supported.

    Why are there fewer runs than requested?

    The preview searches eight calendar years after the selected start. Rare schedules such as leap day may have fewer matches; impossible dates such as February 31 have none. A fixed AWS year may also fall outside the search window. That is different from a syntax error.

    Is my schedule sent to a server?

    No. Parsing, time-zone conversion, and configuration generation happen in your browser. The share button puts the schedule settings in a URL fragment so you can send the link yourself. Anyone with that link can read those settings.
